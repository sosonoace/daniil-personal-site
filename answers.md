# Відповіді на контрольні питання

1. **Чим приватний SSH-ключ відрізняється від публічного?** Приватний ключ зберігається тільки на моєму комп’ютері та підтверджує мою особу. На GitHub додається публічний ключ: сервер використовує його, щоб перевірити підпис, створений відповідним приватним ключем. Приватний ключ не можна передавати, бо з ним інша людина зможе видавати себе за власника.
2. **Навіщо потрібен ssh-agent?** Він тимчасово зберігає розблокований SSH-ключ у пам’яті, щоб не вводити пароль ключа щоразу під час з’єднання.
3. **Що означає «You’ve successfully authenticated, but GitHub does not provide shell access»?** GitHub успішно розпізнав обліковий запис за SSH-ключем. Інтерактивний командний рядок GitHub не надає, але Git-команди через SSH працюють.
4. **Яка різниця між `git add`, `git commit` і `git push`?** `git add` готує вибрані зміни до збереження; `git commit` зберігає їх у локальній історії; `git push` надсилає коміти до віддаленого репозиторію.
5. **Чому головна сторінка має називатися `index.html`?** Вебсервери зазвичай шукають `index.html` як сторінку за замовчуванням, коли відвідувач відкриває адресу папки або сайту.
6. **Чому `/css/style.css` може не працювати на GitHub Pages, а `css/style.css` працює?** Шлях із початковим `/` веде від кореня домену, тоді як проєктний сайт розміщений у підпапці репозиторію. Відносний шлях `css/style.css` рахується від поточної сторінки й працює в такій підпапці.
7. **Які три команди оновлюють опублікований сайт?** `git add .`, `git commit -m "Опис змін"` і `git push`.
8. **Чим відрізняються адреси `my-site` і `<логін>.github.io`?** Проєктний сайт `https://<логін>.github.io/my-site/` міститься в підпапці конкретного репозиторію. Репозиторій із назвою `<логін>.github.io` публікує персональний сайт без назви репозиторію в адресі: `https://<логін>.github.io/`.
